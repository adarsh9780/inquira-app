# System Architecture

Inquira is a desktop analysis workspace built around one loop: ask a question, generate Python, run it locally, inspect the result, edit the code when needed, and save the artifacts with the project.

## Tech Stack

- **Desktop shell**: Tauri and Rust
- **Frontend**: Vue with Vite
- **Backend**: Python and FastAPI
- **Local execution**: Workspace-scoped Jupyter runtime
- **Data engine**: Embedded DuckDB
- **Agent workflow**: LangGraph
- **Model access**: OpenRouter, direct provider keys, and local Ollama setups
- **Persistence**: Local workspace folders, SQLite metadata, DuckDB files, and turn-owned artifacts

## Core Components

### Desktop Shell

The Tauri shell provides the native desktop window, local filesystem access, and the bridge for terminal sessions and desktop packaging.

### Frontend Workspace

The workspace UI is split into analysis surfaces:

- Chat for natural-language requests and follow-ups
- Code for generated and user-edited Python
- Tree for conversation and turn navigation
- Table, chart, and output panes for results
- Terminal for direct workspace-level commands
- Settings for provider keys, models, appearance, workspace state, and runtime controls

### Python Backend

FastAPI coordinates the local app runtime:

- Workspace creation and deletion
- Dataset ingestion
- DuckDB access
- Jupyter kernel lifecycle
- Python execution
- Artifact capture and export
- Conversation and turn persistence
- Provider and model configuration

### AI Agent Workflow

The agent workflow uses the selected model provider to turn a user request into Python. The app can then execute that code locally, capture the output, and save the resulting artifacts.

The generated code is not hidden. The user can inspect it in the editor, switch between agent and edited versions, rerun it, and debug failures through the output pane or terminal.

## Data Flow

```text
Local files
  -> dataset import
  -> local DuckDB workspace
  -> prompt context and schema hints
  -> generated Python
  -> local Jupyter execution
  -> tables, charts, logs, scalars, and artifacts
  -> persisted workspace state
```

Workspace data is stored locally by default. Cloud model providers receive only the prompts, schema/context, attachments, or snippets that the app sends for the selected request. Local execution can still access network resources if the executed code does so.

## Artifact Model

Inquira saves more than the final answer. A turn can own:

- Generated Python
- Table artifacts
- Chart artifacts
- Scalar values
- Output logs and errors
- Metadata and previews

This lets you reopen a workspace and inspect how an answer was produced instead of rebuilding the analysis from scratch.

## Local Execution Security

Python generated by the AI, Python run from the editor, and terminal commands execute locally with your operating-system user permissions. They are not sandboxed and may access files, processes, network resources, environment information, and memory available to your user account.

Inquira applies prompts, policy checks, timeouts, workspace organization, consent gates, and output bounds to reduce some risk. These controls are not a security boundary. Review code before running it, use trusted workspaces and prompts, and maintain backups of important data.

## Current Product Boundary

The current public app is strongest for local file analysis and Python-backed exploration. Direct database connectors, deeper RAG workflows, team collaboration, MCP integration, and managed enterprise controls belong to future or commercial editions.
